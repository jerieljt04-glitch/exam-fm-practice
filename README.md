# Exam FM Practice Platform

A full-stack, timed practice environment for **SOA Exam FM (Financial Mathematics)**.
Thirty parameterized multiple-choice questions, 150 minutes, a pause/resume clock, and a
diagnostic report with a complete stage-by-stage KaTeX derivation for every question. A mock
sitting mixes difficulties the way a real form does: roughly half the paper is multi-step
synthesis work and the rest is direct and intermediate evaluation.

> Independent study tool. Not affiliated with, endorsed by, or sponsored by the Society of
> Actuaries. All question content is generated by this application.

## Opening it as an application

Build the macOS app once:

```bash
npm install && npm run app:build
```

That installs **Exam FM Practice.app** in `~/Applications` and adds an **Exam FM Practice** shortcut
to the Desktop. After installation, double-click either icon or keep the app in the Dock; no
Terminal window is needed to open the exam.

The app owns no logic of its own. It starts the same production server `npm start` runs, waits
for it to answer, opens the exam in your browser, and then **exits**. That exit is deliberate:
macOS does not re-run a running app's executable when its Dock icon is clicked, and this app has
no window to activate — so if it stayed resident, the second click and every click after it would
do nothing at all. Exiting means every click reopens the exam.

The server therefore keeps running in the background after the app quits. Clicking again is
instant, because the launcher finds it already up and just reopens the page — unless the source
files or the compiled build are newer than the version the background server loaded, in which
case it rebuilds or restarts first. To shut it down:

```bash
npm run app:stop
```

On the first launch the app installs dependencies and builds if needed (about a minute, with a
notification), and it rebuilds automatically whenever the source files are newer than the last
build. Anything that goes wrong is reported in a dialog, with detail in
`~/Library/Logs/exam-fm-practice.log`.

It serves on port **4173** rather than 3000, so it never collides with a `npm run dev` session,
and it checks that whatever answers on that port is actually this application before reusing it.
Set `EXAM_FM_PORT` before `npm run app:build` to change the port.

The repository path is baked into the app at build time, so re-run `npm run app:build` if you
move the project. To build an app pointing at a different checkout, set `EXAM_FM_REPO`.

### Driving the app from a terminal

```bash
open -a "Exam FM Practice"     # same as clicking the icon: starts it if needed, opens the exam
npm run app:stop               # stop the background server
npm run app:build              # rebuild the bundle (after moving the project, or changing the port)
```

`open -a` works from any directory; the `npm` scripts must be run from the project folder.

## Exam blueprint

Defined once in [`lib/exam-config.ts`](lib/exam-config.ts) and read by every layer:

- **30** multiple-choice questions, **five** options each (A–E), listed in ascending
  numeric order the way the real CBT presents them.
- The correct answer is **evenly distributed across A–E** and never predictable from the
  template. Because options are listed in ascending order, the key's position is decided by how
  many distractors fall below the correct value — so the engine draws the target position first
  and then chooses distractors that realise it. A template whose distractors are symmetric used
  to put its answer in the same slot on *every* draw, which is how a Loans practice set once came
  back with all ten answers at C.
- **150 minutes** (9000 seconds) of active time.
- **Current SOA syllabus ranges** translated to a 30-question sitting: Time Value of Money
  2–4, Annuities 6–9, Loans 5–7, Bonds 5–7, and Asset-Liability Management 6–9.
- A **mixed difficulty** sitting, with fresh parameters when an archetype repeats. Each domain
  contributes a set quota of level 3+ items (`EXAM_ADVANCED_COUNTS`) and fills its remaining
  slots with direct and intermediate work, plus at most two qualitative items. Material the
  current syllabus excludes — swaps, determinants of interest rates, sinking funds, dollar- and
  time-weighted returns, second-order price approximations, bond valuation between coupon
  dates — is not in the bank at all.
- The difficulty mix is this platform's own approximation. The SOA publishes topic weights but
  no difficulty breakdown, so these counts are a study choice, not a published statistic.
- A **70% (21/30)** benchmark used only for the report's study signal.

### Difficulty taxonomy

| Level | Name | What it demands |
| --- | --- | --- |
| 1 | Basic | A direct evaluation or conceptual recognition item. Available in custom Practice Mode. |
| 2 | Intermediate | Two cash flow streams equated across one structural change. |
| 3 | Advanced | A chain of **at least three interdependent sub-problems**. |
| 4 | Elite synthesis | Multi-period state tracking: rate resets, refinancing, multi-phase payment streams. |

These are internal study labels, not official SOA ratings. Levels 3 and 4 are still enforced
rather than merely asserted: `lib/engine/templates/index.ts` refuses to load if a level 3+
template declares fewer than three chained steps, and the test suite fails if its rendered
solution shows fewer than three stages.

A question is tagged with the syllabus areas it actually assesses. Shared discounting and
annuity algebra is treated as a prerequisite rather than a second topic, so a template is never
given an extra tag just to look cross-cutting — that mislabelling is what previously let a
single-subject practice set serve questions about another subject.

### Coverage

| Domain | Templates | Covers |
| --- | --- | --- |
| Time Value of Money | 30 | simple and compound interest and discount, nominal rates, force of interest (constant, varying, piecewise), equivalent measures, real rates, equations of value, early-payment discounts, penalties, current value |
| Annuities & Cash Flows | 69 | level, due, deferred, continuous, m-thly, perpetual, arithmetic and geometric, multi-phase and every-k-years streams; funds with withdrawals; reinvested payments; choosing the correct equation of value |
| Loans & Amortization | 44 | balances, principal and interest portions, payments set as a multiple of interest, refinancing and reamortization, balloon and drop payments, missed and extra payments, lender reinvestment, payoff counts and dates |
| Bonds | 30 | price, yield, premium/discount, amortization entries and book values solved forward and backward, related-price problems, callable bonds, reinvested coupons, bonds bought with a loan, varying and stepped coupons |
| General Cash Flows, Portfolios & ALM | 29 | spot and forward rates, NPV and project yields, Macaulay and modified duration, convexity, first-order approximations and their error, exact matching, full and Redington immunization |

There are **202 templates in total**: 185 parameterized calculations and 17 qualitative items
(true/false statements, equations of value, naming a technique). 81 are level 3+.

Each template is filed under the skill it assesses rather than the instrument in its story, which
is why spot-curve and forward-rate work sits under General Cash Flows, Portfolios & ALM — the
topic the SOA syllabus places it in — instead of under Bonds.

### Relationship to the SOA sample questions

The bank is modelled on the Society of Actuaries' *Exam FM Sample Questions* (the August 2026
revision, 460 items). Every template names, in `soaSamples`, the sample questions whose type it
reproduces; together they cover 400 of the 460. The sample questions are copyrighted by the SOA
and are not reproduced: each template writes its own stem in the sample set's voice and draws
its own figures.

The sample set also pins down *interpretation*. [`scripts/audit_checks/anchors.py`](scripts/audit_checks/anchors.py)
feeds 351 SOA sample questions, with their published figures, to the independent checker for
the matching template, and requires the SOA's published answer to come back. That catches the
cases a self-consistent engine cannot: a balloon payment that should replace the last regular
payment rather than follow it, a bond amortization entry indexed from the wrong end, a callable
bond priced at the wrong redemption date.

Numerical questions receive fresh parameters each sitting. A mock exam draws across all four
difficulty levels; the Practice Mode filters narrow that pool to chosen subjects and levels.

### House style

The sample set is written to a tight pattern, reproduced by
[`lib/engine/templates/soa/kit.ts`](lib/engine/templates/soa/kit.ts) and
[`lib/engine/style.ts`](lib/engine/style.ts):

| Convention | In the sample set | Here |
| --- | --- | --- |
| Currency symbols | none | none; amounts are bare numbers |
| Grouping commas | only from 10,000 up: `4695`, `20,689` | same |
| Rates | no trailing zeros: `6%`, `7.25%`; "an annual nominal interest rate of 6% convertible semiannually" | same |
| Closing line | "Calculate ..." or "Determine ...", often after a lead-in ("Using an annual effective rate of 5%, calculate ...") | same, on its own line |
| Options | ascending; often evenly spaced, sometimes built from specific mistakes | a mix of both, per draw |
| Qualitative items | I/II/III statements with "I only ... not given" or "None ... II and III only" schemes | same two schemes, key drawn evenly across A–E |

So a question reads:

> A 10,000 par value 10-year bond with an annual coupon rate of 8% paid annually is bought at a
> premium to yield an annual effective rate of 6%.
>
> Calculate the interest portion of the 7th coupon.

Solutions are this platform's own: a stage-by-stage derivation in the same numeric conventions.

## How questions are generated

Each template declares a `generate(rng)` that draws its own parameters, solves the chain, and
derives four distractors by *simulating a specific mistake*:

| Error model | Example |
| --- | --- |
| `ANNUITY_DUE_CONFUSION` | valuing end-of-period payments with `ä` |
| `SIMPLE_INTEREST_ERROR` | `1 + it` where `(1+i)^t` is required; unweighted cash-flow exposure |
| `OFF_BY_ONE_PERIOD` | `n - t` instead of `n - t + 1`; counting the drop payment as a full payment |
| `NOMINAL_RATE_ERROR` | using `i^(12)` directly as a monthly rate; halving an annual effective yield for semiannual coupons |
| `CALCULATION_DISTRACTOR` | computing the interest component when principal was asked; a balloon payment where a drop payment was wanted |

On a level 3+ item the distractor re-runs the *whole* chain with one flawed stage, so a wrong
answer is reachable by a coherent mistake rather than by arithmetic noise. The review names the
exact error behind the option the candidate chose.

Options are then filtered for plausibility: a non-finite value, a negative amount where the
quantity must be positive (an outstanding balance of `-10,207` gives the answer away), or a
value less than a fifth or more than five times the correct one is dropped rather than printed.

Many sample questions list evenly spaced options (4.33%, 4.43%, 4.53%, ...), so some draws use
such a ladder around the key, with a step chosen from the answer's size; others use the modelled
mistakes and top up with ladder rungs where a mistake collides with the key or is implausible.
Either way the key's position is drawn first. The test suite fails the build
if any letter holds less than 12% or more than 28% of correct answers, or if a single template
puts more than 60% of its answers in one slot.

### Self-verification

Rule four of the authoring standard is that a question is solved numerically before it ships.
Templates implement that literally: each publishes a `checks` array of invariants it re-derives
independently —

- the prospective balance equals the retrospective balance;
- re-pricing at a solved yield reproduces the price it was solved from;
- the closed form matches a direct cash-flow summation, or Simpson's rule on the defining integral;
- the asset split matches the liability in both present value and duration;
- a solved rate, term or amount reproduces every figure printed in the question.

`npm run test:engine` runs every template 40 times and fails the build if any check comes back
false — over 8,000 assertions on the current library.

### Independent audit

The self-checks share code with the generators, so they cannot catch a formula that is wrong in
both places. `npm run audit` dumps generated instances and re-derives every answer in Python
([`scripts/audit_checks/`](scripts/audit_checks)) by a different route — explicit cash-flow sums,
period-by-period ledgers, numerical integration, bisection, finite differences — and checks
that:

- the keyed option carries that answer and no distractor coincides with it;
- every rate and decimal figure printed in the stem is exactly a value the key was computed
  from, so a rounded rate in the question can never silently differ from the one used;
- the worked solution states the answer;
- for qualitative items, the structure is sound and, where a check exists, the keyed text is right.

It then replays the 351 SOA sample questions in the anchor list. Pass a draw count to widen the
sample, e.g. `npm run audit -- 40`.

### Reproducibility

All randomness flows through a seeded PRNG. Each question stores its seed alongside its drawn
parameters (`variables._seed`), so a persisted question can be replayed to recover its worked
solution — the schema keeps `solutionSteps` on the template, not on the instance. The replayed
question text is compared with the stored text before the replayed solution is trusted, so a
template edited after a sitting falls back to the template's reference solution rather than
showing a derivation that does not match the question.

## Question markup

Question text, options and solutions are authored in a small, unambiguous dialect
(see [`lib/math/markup.ts`](lib/math/markup.ts)):

| Syntax | Meaning |
| --- | --- |
| `\$` | a literal dollar sign — currency, never math |
| `$ ... $` | inline math (must close on the same line) |
| `$$ ... $$` | display math (may span lines) |
| `**bold**`, `*italic*`, `` `code` `` | emphasis, and it may wrap inline math |

Currency is always written through `lib/engine/format.ts`, which escapes the `$`. That is what
keeps a sentence such as

```
A loan of \$160,000 ... immediately after the $12^{\text{th}}$ payment is made.
```

from having its price swallow the opening math delimiter. The tokenizer also recognises
*unescaped* currency so rows written by earlier versions still render correctly: a `$` followed
by a complete number is read as currency only when it either never closes on that line or would
enclose a sentence rather than an expression.

Nothing is injected as raw HTML — the renderer emits React elements — so question text loaded
from the database cannot inject markup into the exam interface.

## A sitting ends when you close it

An exam is a single sitting. There is no resuming one, and no way to land back
on a paper you have walked away from:

- The exam page reports in every 10 seconds. If it stops for 30 seconds the
  sitting is marked `ABANDONED` — closing the tab ends the exam.
- A reload is not a close. The page resumes reporting within a second or two, so
  it never crosses the deadline. A heartbeat arriving *after* the deadline does
  not revive a dead sitting.
- Reopening an ended exam redirects to the landing page with a note saying so;
  the API answers `410 Gone`. It is never graded and has no report.
- Starting a new exam retires anything the candidate left open, so the back
  button cannot resurrect a stale paper either.
- The application icon always opens the landing page, never an exam.

Every sitting therefore draws 30 fresh problem instances across the difficulty range. When an
archetype repeats, it receives new numbers, names, answers and distractors, so the actual
calculation chain is different.

## Practice, history, and analytics

- Practice Mode supports 5, 10, 15, or 30 questions, subject and difficulty filters, timed or
  untimed work, immediate feedback, worked solutions, and an optional formula sheet.
- Subject filtering is **strict**: a set drawn for one subject contains that subject only. All
  subjects start selected, so the first click narrows the set to the subject clicked rather than
  excluding it, and "Select all" restores the full range. Where a subject cannot offer as many
  distinct methods as the requested length, its pool is cycled with fresh parameters so the set
  still reaches the requested number of questions.
- Completed attempts and template-level mastery are stored in the browser. Review Due uses spaced
  intervals, while Retry Mistakes builds a targeted quiz from the most recent misses.
- Each question records active time, confidence (Sure, Unsure, or Guess), and an optional
  self-reported **Calculator used** mark. The report compares calculator/no-calculator accuracy and
  average pace and highlights overconfident errors and lucky guesses. Physical calculator use is
  necessarily self-reported because a browser cannot observe its keys.

## Timing and pause/resume

Remaining time is recomputed from wall-clock timestamps on every tick rather than by
decrementing a counter, so a throttled background tab, a page reload or a server restart
cannot hand the candidate extra time or take any away.

- Pausing records the moment; resuming adds the elapsed interval to `pausedTimeMs`.
- While paused the questions are blurred, `aria-hidden`, and covered by a modal that cannot be
  dismissed with Escape or an outside click.
- A pause still open at submission is closed out before grading, so it is never counted as
  active exam time.
- Revisiting a completed report never re-grades or moves the end time.
- Closing the tab does **not** pause the clock: time is measured against the
  wall clock, so pause before you leave if you intend to come back within the
  30-second window.

## Testing

```bash
npm test
```

- **`test-markup.ts`** — table-driven tokenizer cases, including the exact question text that
  once rendered as literal `$12^{\text{th}}$`, plus degenerate input (unterminated delimiters,
  empty delimiters, emphasis spanning math).
- **`test-engine.ts`** — 100 generated exams (3000 questions) checked for the blueprint
  distribution, the per-domain level 3+ quota and overall difficulty mix, exactly one correct
  option, five distinct and plausible labels, and an error model on every distractor. Then every
  template is generated 40 more times so that coverage does not depend on which templates happen
  to be sampled, and each draw is checked for:
  - no markup leaking into rendered prose (`\frac`, `^{`, `**`, …);
  - every math expression parsing under KaTeX;
  - **no unescaped `%` inside math** — in LaTeX that opens a comment and silently swallows the
    rest of the expression, which is how a spot curve once rendered as `s₁ = 4.07` with the sign
    missing;
  - at least three stage headings in a level 3+ solution;
  - every generator self-check passing.

  Finally the repository flow: pause accounting, grading, report idempotency, and a review
  built from a history that names retired templates.

```bash
npm run audit            # independent Python re-derivation + SOA anchors
npm run audit:anchors    # the SOA anchors alone
```
